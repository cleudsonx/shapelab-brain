# Shapelab — Base de Conhecimento Viva (Lessons Learned)

Registro consolidado de aprendizados reais extraídos de **Mr. Coach (`B2B-personal-ia`)**, **ReformAI** e **Smart EV Hub**.

| ID | Data | Origem | Categoria | Causa Raiz / Problema | Solução Definitiva (Padrão ShapeLab) |
| :--- | :--- | :--- | :--- | :--- | :--- |
| `LL-001` | 2026-11 | `B2B-personal-ia` | Fintech / BCB 4893 | Webhooks concorrentes do Asaas ou cliques duplos em saque podiam gerar condição de corrida (*double-spend*). | Lock pessimista (`SELECT ... FOR UPDATE`), idempotência por `event_id UNIQUE` e trilha imutável `financial_audit_ledger` (WORM SHA-256) com split assinado via JWS. |
| `LL-002` | 2026-11 | `B2B-personal-ia` / `ReformAI` | Segurança / Auth | Fluxos públicos de checkout ou chaves/fallbacks estáticos em rotas privadas permitiam risco de *account takeover* ou bypass. | Guard centralizado *fail-closed* (`Depends` no FastAPI / `_guard.ts` no Worker), PBKDF2 100k iterações ou Argon2id, `checkout_nonce` de uso único e bloqueio de contas sintéticas (`wa_*`, `aluno_*`). |
| `LL-003` | 2026-11 | `B2B-personal-ia` | WhatsApp / Growth | Oscilações na API de mensageria ou botões > 20 caracteres quebravam fluxos críticos de treino/cobrança. | Arquitetura Dual-Channel: Meta Cloud API primária + fallback automático para Evolution API convertendo botões em menu numérico (`interactive_degraded: true`). |
| `LL-004` | 2026-11 | `B2B-personal-ia` | Flutter UI | Contraste quebrado ao alternar entre Dark e Light Theme e faixas sólidas nas barras do sistema Android/iOS. | `EdgeToEdgeScaffold` acoplado ao `Theme.of(context).brightness` com `systemNavigationBarContrastEnforced: false` e tokens semânticos WCAG. |
| `LL-005` | 2026-11 | `B2B-personal-ia` | Supabase RLS | Políticas RLS consultando `tenant_members` diretamente causavam recursão infinita ou lentidão por reavaliar `auth.uid()` a cada linha. | Função `SECURITY DEFINER` (`get_my_staff_tenants()`) + wrapper `(select auth.uid())` para ativar *initPlan* + índices em `tenant_id` e `client_id`. |
| `LL-006` | 2026-11 | `B2B-personal-ia` / `ReformAI` | DevOps / OTA | Timestamps longos causavam overflow de 32-bit em `versionCode`; Service Workers serviam `AssetManifest`/`FontManifest` stale causando tela branca; deploys repetidos estouravam cota 429 do Firebase Hosting. | Build monotônico `YYYYMMDDNN`, `initAssetCacheGuard` injetando `?_b=BUILD` + `cache: 'no-store'`, detector `PwaUpdateWrapper` com anti-loop (`reset()` quando `serverBuild <= localBuild`), GC pré-deploy no Firebase Hosting (mantendo `live` + 2 rollbacks) e `SemVer+build.<run>.<sha>` no backend. |
| `LL-007` | 2026-11 | `ReformAI` | Segurança / WebAuthn | Endpoints FIDO2 que validavam apenas `clientDataJSON` ignorando `attestationObject`, mantendo desafios em memória do Worker e sem verificar assinatura ECDSA nem regressão de `signCount` permitiam replay cross-isolate, falsificação de asserção e clonagem silenciosa de Passkeys. | Decodificar `attestationObject` CBOR -> `authData` -> chave pública COSE (`ES256`/`RS256` -> SPKI PEM) sem dependências externas; validar `rpIdHash` (tempo constante), flags `UP`/`UV` e origem exata; verificar assinatura sobre `authData || SHA-256(clientDataJSON)`; persistir desafios no banco com consumo atômico single-use (`UPDATE ... WHERE consumed_at IS NULL AND expires_at > now`, exigindo `changes === 1`); revogar credencial se `signCount` não avançar (permitindo `0/0` para Passkeys sincronizadas) e emitir sessão real com hash + cookie `HttpOnly`. |
| `LL-008` | 2026-11 | `shapelab-brain` | SRE / Observabilidade | Acoplar dependências externas (DB/Redis) na probe `/health/live` derrubava pods saudáveis em cascata durante oscilações de 5 segundos; e exceções HTTP 500 vazavam URLs de banco com senhas e DSN para usuários. | Desacoplar `/health/live` (processo responsivo) de `/health/ready` (Deep Health paralelo com timeout de 2s); sanitizar 100% dos erros 500 em produção retornando apenas `correlation_id` e redigir segredos nos logs. |
| `LL-009` | 2026-11 | `Smart-EV-Hub` | DevOps / Cloud Run | Containers usando `CMD uvicorn` em shell form engoliam `SIGTERM` provocando corte bruto de conexões em 10s; e deploys sem tag candidata viravam tráfego para revisões com falha. | Usar exec form (`ENTRYPOINT ["python", "-m", "app.server"]`) como PID 1 com dreno de conexões até 9s e deploy com `--no-traffic --tag=candidate` antes do cutover Blue-Green em `southamerica-east1`. |
| `LL-010` | 2026-11 | `B2B-personal-ia` / `ReformAI` | Fintech / Segurança | Falhas em validação de JWS podiam aceitar `alg: none` ou sofrer *key confusion* (ES256 -> HS256); e contas de teste (`is_demo=True`) podiam contaminar faturamento real, webhooks de produção e disparar mensagens WhatsApp reais. | Algoritmo pinado no `kid` com Compact Serialization RFC 7515; RLS com `is_demo` imutável em FKs compostas; e dispatcher com fail-closed roteando eventos demo para `demo_notification_sink` com PII mascarada. |
| `LL-011` | 2026-11 | `B2B-personal-ia` / `Smart-EV-Hub` | Backend / Multi-Tenant | Backend com chave `service_role` ignora RLS do PostgreSQL por padrão (`BYPASSRLS`), criando vulnerabilidades de Cross-Tenant IDOR caso endpoints não apliquem escopo de tenant em queries mutativas e botões interativos. | Aplicação de guards fail-closed (HTTP 403 padrão), inclusão forçada de `.eq("tenant_id", caller_id)` em todas as mutações e bloqueio estrito contra sobrescrita de vínculo de tenant em cadastros rápidos/checkout. |
| `LL-012` | 2026-11 | `B2B-personal-ia` / `ReformAI` | Concorrência / FinOps | Race conditions sob concorrência pesada em webhooks de pagamento (double-credit) e chamadas paralelas de LLM permitiam estouro de cotas e bypass de cobrança antes da gravação de uso no banco. | Padrão Durable Lease (`claim_token` UUID + TTL + RPC de liberação em falha transitória) para webhooks e padrão *Reserve-Execute-Release* atômico pré-LLM para controle de cotas de IA sem race conditions. |
| `LL-013` | 2026-11 | `ReformAI` | CI/CD / Submódulos | Checkout padrão `submodules: true` no GitHub Actions falha quando o submódulo privado `.shapelab` não possui `SHAPELAB_BRAIN_PAT` configurado no repositório ou em forks/runners públicos, quebrando toda a esteira CI/CD antes dos testes e deploy. | Desacoplar `actions/checkout@v4` (sem `submodules: true`) da inicialização do submódulo em step dedicado com `continue-on-error: true`: injetar `x-access-token:${SHAPELAB_BRAIN_PAT}` via `url..insteadOf` apenas se o secret existir, rodar `git -c protocol.version=2 submodule update --init --depth=1 .shapelab || true` e executar `ci_preflight_check.mjs` condicionalmente (`[ -f ... ]`) com `::notice` de degradação graciosa quando indisponível. |
| `LL-014` | 2026-11 | `B2B-personal-ia` / `ReformAI` | CI/CD / FinOps | No GitHub Actions, `paths-ignore: ['.shapelab/**']` ignora arquivos dentro de uma pasta mas **não ignora o gitlink de submódulo** (`.shapelab` sem barra), e cron diário em `brain_sync.yml` + bumps sem `[skip ci]` disparavam runners desnecessários consumindo a cota de minutos (`Actions budget preventing further use`). | Sempre incluir ambos `'.shapelab'` e `'.shapelab/**'` em `paths-ignore`, anexar `[skip ci]` nos commits automatizados de atualização de ponteiro do submódulo (`brain_sync.ps1`, `brain_sync.sh`, `cockpit_server.mjs`) e manter `brain_sync.yml` apenas com `workflow_dispatch` (sem `cron` diário). |
